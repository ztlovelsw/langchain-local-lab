# 第 4 课：历史与状态

上一课的 RAG 每次调用都是“无记忆”的：模型不记得你上一句说了什么。真实应用需要**多轮对话**，而且不同用户/会话之间必须互不干扰。

本课的目标：理解 LangGraph 的 `StateGraph` + `InMemorySaver` + `thread_id` 如何管理会话状态。

## 先看代码

在 `src/langchain_lab/flow.py` 的 `run_memory` 中：

```python
class ConversationState(TypedDict):
    messages: Annotated[list[BaseMessage], add_messages]

def call_model(state: ConversationState) -> dict[str, list[BaseMessage]]:
    response = model.invoke(state["messages"])
    return {"messages": [response]}

builder = StateGraph(ConversationState)
builder.add_node("chat", call_model)
builder.add_edge(START, "chat")
builder.add_edge("chat", END)
graph = builder.compile(checkpointer=InMemorySaver())

config = {"configurable": {"thread_id": "lesson-1"}}
first_state = graph.invoke(
    {"messages": [HumanMessage(content="记住：我叫小林。")]}, config=config
)
second_state = graph.invoke(
    {"messages": [HumanMessage(content="我刚才告诉你的名字是什么？")]},
    config=config,
)
```

关键概念：

- **`GraphState`**：图的“共享黑板”。`messages` 是黑板上唯一的状态。
- **`Annotated[list[BaseMessage], add_messages]`**：告诉图“新消息要追加进列表，而不是覆盖”。这是 `add_messages` 归约器（reducer）的作用。
- **`checkpointer=InMemorySaver()`**：每次调用后把状态存起来。服务端应用通常换成数据库持久化的 checkpointer。
- **`thread_id`**：会话的身份证。同一个 `thread_id` 共享历史，不同 `thread_id` 完全隔离。

## 观察数据流

运行：

```powershell
python run.py --provider offline --stage memory
```

输出：

```text
['好的，我会在本次会话中记住这条信息。', '你刚才说你叫小林。']
```

第二次调用能答出“你刚才说你叫小林”，说明图在第二次调用时**确实把第一次的消息历史喂给了模型**。你也可以在 `call_model` 里加 `print(state["messages"])`，观察每次调用模型收到几条消息：第一次 1 条，第二次 3 条（Human + AI + Human）。

## 亲手改一改

### 1. 验证会话隔离

关键：**隔离发生在“两次调用使用不同 `thread_id`”时**。把第一次调用的 `config` 改成 `thread_id="thread-A"`，第二次调用改成 `thread_id="thread-B"`：

```python
first_state = graph.invoke(
    {"messages": [HumanMessage(content="记住：我叫小林。")]},
    config={"configurable": {"thread_id": "thread-A"}},
)
second_state = graph.invoke(
    {"messages": [HumanMessage(content="我刚才告诉你的名字是什么？")]},
    config={"configurable": {"thread_id": "thread-B"}},
)
```

第二次的回答会变成：

```text
好的，我会在本次会话中记住这条信息。
```

而不是“你刚才说你叫小林” —— 因为 `thread-B` 的历史是空的，模型不知道“小林”。两个会话各存各的状态，互不共享。

> 注意：如果两次调用都用同一个新 `thread_id`，它们仍然共享历史（都在同一会话里），也就不会“失忆”。只有两个值不同，才能看到隔离。

### 2. 把隔离和共享对照起来看

分别打印三种组合的结果：

- 两次都用 `"lesson-1"`：共享历史，能答出“小林”（原始 `run_memory` 的行为）；
- 第一次 `"thread-A"`、第二次 `"thread-B"`：不共享，答不出“小林”；
- 两次都用 `"thread-B"`：又共享了。

把三次输出并排对比，`thread_id` 的作用就一目了然。

### 3. 换个问题链

连续问三次：先“记住我喜欢火锅”，再“我喜欢什么？”，最后“我上次说的城市是？”——观察模型如何利用越来越长的历史。注意离线模型的回答逻辑是写死的（见 `models.py` 的 `_respond`），真实模型才能灵活利用完整历史。
