# 第 2 课：结构化输出

上一课我们用 `prompt | model | StrOutputParser()` 拿到一段字符串。真实应用很少只要一段话：你要的是一个可以 `plan.destination`、`plan.days` 这样直接访问的 Python 对象，而不是自己写正则去抠 JSON。

本课的目标：理解 **schema（模式）** 如何约束模型输出，以及 LangChain 如何把模型的文本解析回 Python 对象。

## 先看代码

在 `src/langchain_lab/flow.py` 的 `run_structured_output` 中：

```python
class TravelPlan(BaseModel):
    destination: str = Field(description="目的地")
    days: int = Field(description="旅行天数")
    highlights: list[str] = Field(description="亮点列表")

parser = PydanticOutputParser(pydantic_object=TravelPlan)
prompt = ChatPromptTemplate.from_messages(
    [
        ("system", "只输出 JSON，不要输出 Markdown。\n{format_instructions}"),
        ("human", "请为我规划一个两天的重庆旅行。"),
    ]
)
chain = prompt | model | parser
plan = chain.invoke({"format_instructions": parser.get_format_instructions()})
```

三件新东西：

1. **`TravelPlan(BaseModel)`**：用 Pydantic 描述“模型必须输出什么”。每个字段有类型（`str`、`int`、`list[str]`）和说明（`description`）。
2. **`PydanticOutputParser`**：把 schema 翻译成模型能读懂的“格式说明”，再在另一端把模型输出的 JSON 解析回 `TravelPlan` 对象。
3. **`parser.get_format_instructions()`**：生成的说明文本会被注入 system prompt。你可以运行下面的命令，看看它长什么样。

## 观察数据流

运行：

```powershell
python run.py --provider offline --stage structured
```

你会看到 `TravelPlan` 对象被 `model_dump()` 成了字典打印出来。在 `run_structured_output` 里加一行：

```python
print(parser.get_format_instructions())
```

你会发现：所谓“结构化输出”，就是 **在提示词里告诉模型输出 JSON → 模型输出文本 → parser 把文本解析成对象**。没有魔法，只有约定。

## 亲手改一改

### 1. 增加一个字段

给 `TravelPlan` 增加 `budget: int = Field(description="预算（元）")`，重新运行：

- 离线模型：`PydanticOutputParser` 会抛 `OutputParserException`，提示 `budget Field required` —— 因为离线模型返回的 JSON 里没有 `budget`，解析器不会“猜”，它要求模型输出完全符合 schema。这正好说明：**schema 只是约束，真正填充值的是模型**。
- 真实模型（`--provider openai`）：它通常会遵循 `format_instructions` 补出合理的预算，因为真实模型真的会“读”提示词。

> 第 1 课 README 里说“给 `TravelPlan` 增加 `budget: int` 字段，看看离线模型和真实模型分别会怎样处理 schema”——上面就是你观察到的结论：离线模型直接解析失败，真实模型会补字段。

### 2. 让离线模型支持新字段

打开 `src/langchain_lab/models.py`，在 `OfflineChatModel._respond` 的 JSON 分支里加上 `"budget": 2000`。注意：这是**教学替身**的局限，真实模型不需要你手写返回值。

### 3. 试试解析失败

把 `days` 的类型改成 `str`，或者故意让模型返回 `days: "两天"`，观察 `PydanticOutputParser` 抛出的 `OutputParserException`。解析器不会“猜”，它会明确告诉你哪里不符合 schema。
